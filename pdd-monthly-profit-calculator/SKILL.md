# 拼多多月度利润核算

## 用途

根据拼多多投流截图、成本表和订单文件，按商品 ID 逐单核算商品毛利，再扣除投流总花费，输出中文结论和可追溯的客户核对版 Excel。

**核心原则：可核对比看起来完整更重要。缺成本时直接暂算并清楚标注，绝不猜测成本。**

## 必须输入

1. 拼多多投流数据截图：必须能看到日期范围和“总花费(元)”。
2. 商品成本 Excel：至少包含商品 ID 和单件“总成本”。
3. 月度订单 CSV、XLSX 或 XLS：字段要求见 `references/字段与口径.md`。

如果截图日期或总花费无法辨认，先请用户补清晰截图。不要自行推测。

## 核算流程

1. 查看截图，记录开始日期、结束日期和总花费。截图显示 `1.31万` 时按 `13,100元` 暂录，并标记为近似值。
2. 加载工作区依赖，取得 Python、Node.js 和 Node 模块目录。
3. 运行 `scripts/analyze_profit.py`，生成分析 JSON。
4. 检查 JSON 中的成本冲突、未匹配订单、排除订单和净利润。
5. 运行 `scripts/build_report.mjs`，生成客户核对版 Excel。
6. 打开或检查生成文件，确认工作表、公式、金额和中文说明正常。
7. 向用户交付 Excel，并在聊天中给出简洁核算摘要。

## 计算规则

- 只统计截图日期范围内的订单，开始和结束日期均包含当天。
- 排除取消、待付款、未付款、退款、退货和售后处理中的订单。
- 按商品 ID 匹配成本表与订单表。
- 订单总成本 = 单件总成本 × 商品数量。
- 商品毛利 = 商家实收金额(元) - 订单总成本。
- 投流后净利润 = 商品毛利合计 - 投流总花费。
- 相同商品 ID、相同总成本的重复行可以去重。
- 相同商品 ID 出现不同总成本属于成本冲突，必须停止最终核算并列出冲突 ID。
- 存在未匹配商品时，继续计算已匹配部分；列出未匹配商品 ID、订单行数、数量和商家实收，并将结果标为“暂算”。
- 未匹配商品不得估算成本，也不得宣称已经得到全店最终利润。
- 未提供的平台技术服务费、税费、仓储费等不计入，并在报告中说明。

## 运行命令

分析数据：

```powershell
& '<Python路径>' '<技能目录>\scripts\analyze_profit.py' `
  --cost '<成本表路径>' `
  --orders '<订单文件路径>' `
  --start 'YYYY-MM-DD' `
  --end 'YYYY-MM-DD' `
  --ad-spend 13100 `
  --shop-name '<店铺名称>' `
  --output '<输出目录>\分析结果.json'
```

生成客户核对版 Excel：

```powershell
$env:CODEX_NODE_MODULES='<工作区依赖返回的 Node 模块目录>'
& '<Node.js路径>' '<技能目录>\scripts\build_report.mjs' `
  --input '<输出目录>\分析结果.json' `
  --output '<输出目录>\店铺_月份利润核算_客户核对版.xlsx'
```

## 交付要求

聊天摘要必须包含：核算日期、有效订单行数、有效商品数量、商家实收、商品总成本、商品毛利、投流总花费、投流后净利润、盈利或亏损、未匹配情况。

Excel 至少包含：`核算说明`、`商品盈亏汇总`、`有效订单明细`、`成本映射`、`未匹配商品`、`排除订单`。投流总花费使用黄色可编辑单元格；净利润和逐单商品毛利保留公式，便于客户复核。

## 常见错误

| 错误 | 正确处理 |
|---|---|
| 把 `1.31万` 当成 `1.31元` | 换算为 `13,100元`，并标记截图金额为近似值 |
| 每个订单只扣一次单件成本 | 必须乘以商品数量 |
| 只看订单状态，不看售后状态 | 两个状态字段都检查 |
| 缺成本仍输出“最终利润” | 输出“暂算”，列出未匹配数据 |
| 成本重复时直接取第一条 | 同成本可去重，不同成本必须中止 |
| 只发一个总数 | 同时交付明细、来源、排除项和公式 |
